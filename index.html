RULE 01

AI 不等於自動化

AI 負責理解、分類、摘要、推理；自動化負責觸發、搬運、通知與執行。

RULE 02

能用規則，就不要硬塞模型

固定條件與狀態判斷，通常規則更穩、更便宜。

RULE 03

保留能用的東西

先找斷點，再決定哪裡值得換，不為了新而整套重做。

STAGE 04 / CASES

看我怎麼把問題接住。

不同技術、同一套思考：理解現場 → 找斷點 → 設計資料流 → 做成可驗證的系統。

CASE 01 / LINE × AI

大量群組訊息，變成找得到的公司知識

BEFORE決策埋在聊天、待辦靠人記、資訊找不到
SOLVEAI 擷取重點 → 摘要 / 待辦 → 累積知識
VALUEAI 負責理解資訊，不負責整個系統。
CASE 02 / PAYMENT × API

跨支付與帳務節點，讓狀態自動對上

BEFORE多系統、多狀態、人工比對
SOLVEAPI / Callback → 自動銷帳與狀態回傳
VALUE這裡幾乎不需要 AI，可靠 API 才是正解。
CASE 03 / BOOKING

人工訂位，重做成可管理的分銷流程

BEFORE同業來訊 → 人工處理 → 資訊分散
SOLVE權限 → 專屬入口 → 訂位 → 統計
VALUE把人記得下一步，變成系統知道下一步。
