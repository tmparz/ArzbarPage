RULE 01

AI 不等於自動化

AI 負責理解、分類、摘要、推理；自動化負責觸發、搬運、通知與執行。

RULE 02

能用規則，就不要硬塞模型

明確條件、固定格式、狀態判斷，通常規則更便宜、更穩。

RULE 03

保留能用的東西

不為了「新」就整套重做。先找斷點，再決定哪裡值得換。

YOUR WORLD / 03

從「很亂」到「跑得動」，
我只做四件事。

不先談框架、不先談模型。先把問題、資料與責任邊界看清楚，再開始做。

CASE 01 / LINE × AI KNOWLEDGE

大量群組訊息，變成找得到的公司知識

真正的問題不是「沒有 AI」，而是決策、待辦與關鍵資訊埋在聊天紀錄裡。

BEFORE群組聊天 → 人腦記憶 → 重複詢問 → 找不到歷史
SOLVE定義重點 → AI 擷取 → 摘要 / 待辦 → 持續沉澱知識
VALUEAI 在這裡負責「理解資訊」，不是負責整個系統。
CASE 02 / PAYMENT × API

跨多個支付與帳務節點，讓狀態自動對上

當流程跨越超商給號、POS、AML 與帳務，核心問題是狀態一致與可追蹤。

BEFORE多系統 → 多狀態 → 人工比對 → 問題難追
SOLVE定義資料格式 → API / Callback → 自動銷帳與狀態回傳
VALUE這裡幾乎不需要 AI。可靠的 API 架構才是正解。
CASE 03 / BOOKING × WORKFLOW

人工訂位，重做成可管理的分銷流程

從角色、權限、入口到訂位與統計，先重整流程，再決定哪些地方自動化。

BEFORE同業來訊 → 人工處理 → 資訊分散 → 月底手算
SOLVE分級權限 → 專屬網址 / QR → 訂位 → 統計同一條線
VALUE把「人記得下一步」變成「系統知道下一步」。
