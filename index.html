我是誰

你好，我是吳政穎，
大家都叫我阿茲。

我的底子是工程：後端、雲端架構、API、資料庫、系統整合、自動化。這幾年把這些能力和 AI 放在一起，專心處理公司裡那些每天都在吃人力的流程。

我很少一開口就推薦工具。我會先搞懂事情現在怎麼被完成、哪一步最常出錯，再決定哪裡值得改、哪裡不要動。很多問題理完流程、接好 API 就解了，用不到模型。

先講清楚

能做、不能做、哪裡有風險，開工前就說。

不硬塞 AI

流程或整合能解決的，就不額外加模型。

要能維護

Demo 能跑不算完成，要接得進日常工作。

看整條線

從使用者、資料、API 到後端一起看。

六站，從聽懂到跑得動。

順序很重要。工具在第四站才出現，前面三站都在搞懂問題。

聽懂現場實際怎麼運作。

第 2 站拆題

把大問題拆成具體卡點。

第 3 站畫流程

第 4 站選解法

第 5 站建置

做過的事

四個現場，四種線。

技術各不相同，做法一樣：先看現場，再把它拆成能運作的系統。

跨境支付 × API

多個支付與帳務節點，讓資料自動對上

原本超商 EC 給號→POS→AML→帳務系統→人工核對
之後各節點以 API 與 Callback 串接→銷帳與狀態自動回傳

交易要可信、可追、可驗證。

旅遊分銷 × 訂位

靠人工處理的同業訂位，變成可管理的分銷流程

原本同業來訊→人工訂位→資訊分散→月底手算統計
之後分級分銷與權限→專屬網址、QR Code→訂位與統計同一處

下一步該做什麼，由系統記得。

LINE × AI 知識

大量群組訊息，整理成找得到的公司知識

原本決策埋在聊天→待辦靠人記→新人問不到
之後自動擷取重點與待辦→每日／每週摘要→知識持續累積

AI 在這裡負責讓資訊能用。

企業 × 數位整合

工具越加越多，系統不跟著變亂

原本多角色→多份資料→多套系統各自為政
之後定義需求邊界、資料流、權限→架構、API、資料庫、工作流一起規劃

做得出來之外，還要能長期運作。
